# BUG-005 — Interconnect decodes on a single address bit

*Injected deliberately, to qualify the testbench. Specification §9.*

| Field | Content |
|---|---|
| **ID** | BUG-005 |
| **Class** | Injected — the fifth of the six §9 qualification bugs |
| **Located in** | `rtl/axi4lite_interconnect.sv`, `decode()` |
| **Detected by** | **Scoreboard + decode test**, which is exactly what §9 assigns it |
| **Test + seed** | `sanity_sys_tb` (directed, 10 of 36 checks) and `sanity_rand_tb` seed 3 (75 of 651) |
| **Status** | Detected, reverted. |

---

## Expected

Specification §4 gives the address map:

```
0x0000_0000 .. 0x0000_0FFF   register file    4 KB
0x0000_1000 .. 0x0000_13FF   memory           1 KB
0x0000_1400 .. 0xFFFF_FFFF   unmapped      -> DECERR
```

§7 says why the gap is there, in the specification itself and before any RTL
existed: *"this is **not** a single-bit decode: `0x1400`–`0x1FFF` must produce
`DECERR` even though it lies inside what a naive `ADDR[12]` decode would route
to memory. That gap exists precisely so the decode is non-trivial and the
`DECERR` path is reachable from a plausible-looking address."*

## The injection

```systemverilog
function automatic dest_e decode(input logic [ADDR_WIDTH-1:0] a);
    if (a[31:14] != '0) return DEST_ERR;
    if (a[12])          return DEST_MEM;
    return DEST_REG;
endfunction
```

Plausible, short, and wrong in two directions at once:

- `0x1400` sets `ADDR[12]`, so it is routed to **memory** instead of returning
  `DECERR`. The memory slave owns 256 words and decodes `ADDR[9:2]`, so
  `0x1400` lands on **word 0** — an address that already holds valid data.
- Everything from `0x2000` to `0x3FFF` passes the `a[31:14] != 0` test and is
  routed as if it were mapped, so a whole 8 KB of unmapped space answers
  `OKAY` or `SLVERR` instead of `DECERR`.

## Detection

**`sanity_sys_tb`, directed — 10 of 36 checks failed.** The first three name the
defect outright:

```
  FAIL   write 0x00001400 -> DECERR                   0x0         (expected 0x3       )
  FAIL   read  0x00001400 -> DECERR                   0x0         (expected 0x3       )
  FAIL     RDATA zeroed on error                      0xbaadbaad  (expected 0x0       )
```

The fourth is the one worth reading twice:

```
  FAIL   memory word 0 untouched by DECERR            0xbaadbaad  (expected 0x11112222)
```

`0xBAADBAAD` is the data the bench wrote to `0x1400` expecting it to be rejected.
It reached memory word 0 and destroyed a value written earlier. **A wrong
response is a wrong answer; a wrong route is data corruption**, and that check
exists because the two are different failures.

**`sanity_rand_tb`, seed 3 — 75 of 651 checks failed**, on the first seed tried,
with no directed knowledge of the address map at all.

## What the signatures say

`scripts/parse_log.py` reduces those 85 failures to **three** normalised
signatures:

```
CHECK:read <N> addr=<H> : RRESP <N>, spec says <N>
CHECK:write <N> addr=<H> strb=<N> : BRESP <N>, spec says <N>
FATAL:sanity_rand_tb failed (seed <N>)
```

Two defect classes and a bench abort — which is the honest count. This is the
whole argument for signatures rather than error totals: "85 failures" is a
number to be frightened of, "reads route wrong and writes route wrong" is a
sentence you can act on.

Run as a full local regression — the ten random seeds plus the three directed
benches — the same injection produces:

```
  13 runs, 2 passed, 11 failed.
  952 failing checks are 13 distinct failures, 13 new since the previous run.
```

Three of those thirteen account for thirty of the thirty-three failing
random-seed results; the other ten are the directed bench naming the specific
boundary. That ratio is what `triage.py` exists to produce, and BUG-005 is the
defect it was first produced on.

## Root cause

A range comparison replaced by a bit test. The two agree everywhere except the
gap the specification put there on purpose, which is why the gap is in the
specification: a decode is only interesting at its boundaries, and a boundary
one address wide is the one an implementation gets wrong.

## Fix

Reverted to the range comparison:

```systemverilog
function automatic dest_e decode(input logic [ADDR_WIDTH-1:0] a);
    if (a <= REG_LIMIT)                  return DEST_REG;
    if (a >= MEM_BASE && a <= MEM_LIMIT) return DEST_MEM;
    return DEST_ERR;
endfunction
```

## Regression

`sanity_sys_tb` 36/36, `sanity_rand_tb` clean across six seeds, no assertion
fired from any of the three bound checker instances, and `c_resp_decerr` back to
7 at the master port and 0 at both slave ports.

## What it confirms about the environment

Three things, and the second is the one that was not guaranteed:

1. **The mechanism §9 assigned it caught it.** The specification predicted, in
   August, which check would find this defect. It did.
2. **Random traffic found it independently**, on the first seed, without being
   told where the boundary is. The directed test knows to try `0x1400`; the
   random bench only knows the map's shape, and that was enough.
3. **The corruption check earned its place.** Four of the ten directed failures
   are response mismatches, which a reviewer would expect. The fifth is a
   memory word that changed when nothing should have been written, and that one
   only fails because someone thought to write down a witness value and read it
   back afterwards.
