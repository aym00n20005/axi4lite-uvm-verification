## Why this one is different

Every other §9 injection goes into the RTL. This one goes into the testbench,
and spec §9 says why:

> "`AWVALID` is master-driven, so no slave-side defect can violate `AWVALID`
> stability — v0.1 of this spec paired that bug with that assertion
> incorrectly. BUG-001 qualifies the checker; BUG-002 is the DUT-side defect
> that the same class of assertion catches."

So the **design pane was clean** for this run and the testbench pane carried the
defect. The checker is bound to the DUT but constrains *both* sides of the
interface.

## Finding a window took some thought

The obvious injection — drop `AWVALID` early — violates nothing. `AWREADY` is
high whenever the register slave is idle, so the handshake completes on the
first cycle and there is never a stalled cycle to withdraw from.

The window is the cycle **after** the accept. `do_write` has fired, `bvalid_q`
is set, and `AWREADY` falls. Holding `AWVALID` one cycle past the handshake and
then dropping it is a withdrawal with `AWREADY` low:

```systemverilog
do @(vif.master_cb); while (vif.master_cb.AWREADY!==1'b1);
@(vif.master_cb);              // hold one cycle too long...
vif.master_cb.AWVALID<=1'b0;   // ...then withdraw while AWREADY is low
```

On the bus this reads as the master offering a second address and then
retracting it. Whether it *meant* to is irrelevant — spec §3 rule 1 forbids
withdrawing `VALID` before `READY` is sampled high, and that is what
`a_awvalid_stable` encodes:

```
(AWVALID && !AWREADY) |=> AWVALID
```

Antecedent true at T+1, consequent false at T+2.

## Result

```
*E,ASRTST (time  75 NS) a_awvalid_stable has failed -- AWVALID deasserted before AWREADY
*E,ASRTST (time 285 NS) a_awvalid_stable has failed
*E,ASRTST (time 495 NS) a_awvalid_stable has failed
```

Three firings, one per write in the sequence.

## The part that matters more than the detection

```
all 5 checks passed
** Report counts by severity
UVM_INFO  : 11
UVM_ERROR :  0
```

**Every functional check passed. UVM reported zero errors.** The protocol was
violated on every write and the data was still correct, because the slave
tolerates the malformed handshake and produces the right result anyway.

A scoreboard could not see this. A directed test could not see this. Reading
back what you wrote proves the *data path* works and says nothing about whether
the *protocol* was obeyed. Functional correctness and protocol compliance are
independent properties, and this run separates them cleanly.

That is the argument for binding a protocol checker, stated as a measurement
rather than an opinion.

## Operational consequence for the September regression runner

The only evidence in the report summary is the **exit code**:

```
Exit code expected: 0, received: 1
```

SVA failures are not UVM errors and do not appear in `Report counts by severity`.
A regression script that decides pass/fail on `UVM_ERROR : 0` — which is the
obvious thing to write — would score this run as a **pass** while the DUT was
being driven illegally three times.

`run_regression.py` (automation plan T1, September) must key on the process exit
code, and should additionally scan for `ASRTST` and report assertion failures
separately from UVM severities. Recorded here so the runner is written correctly
the first time rather than after a silent regression.

## Reproducing it

The injected bench is not committed, for the same reason the injected design
panes for BUG-003 and BUG-006 are not: deliberately broken code in the tree is a
trap for whoever reads it next. It is three lines from a file that *is*
committed.

Take `tb/uvm/bug006_min_tb.sv` and, in the AW branch of `axi_drv::wr()`,
replace:

```systemverilog
do @(vif.master_cb); while (vif.master_cb.AWREADY!==1'b1);
vif.master_cb.AWVALID<=1'b0; end
```

with:

```systemverilog
do @(vif.master_cb); while (vif.master_cb.AWREADY!==1'b1);
@(vif.master_cb);              // hold one cycle too long...
vif.master_cb.AWVALID<=1'b0;   // ...then withdraw while AWREADY is low
end
```

Design pane: `sim/playground_smoke_design.sv`, unmodified. No source file in
the repository was changed for this qualification.
