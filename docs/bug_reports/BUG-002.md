# BUG-002 — Register slave asserts BVALID before W is accepted

*Testbench qualification bug, injected deliberately. Spec §9.*

| Field | Content |
|---|---|
| **ID** | BUG-002 |
| **Class** | Injected for qualification — not a genuine defect |
| **Detected by** | SVA `a_bvalid_not_early` (`tb/interface/axi4lite_if.sv:224`) |
| **Test + seed** | `sanity_tb` and `sanity_mem_tb`, directed — no randomisation, no seed |
| **Simulator** | Verilator 5.050, `--binary --assert --timing` |
| **Date** | 18 August 2026 |
| **Status** | Detected, reverted. RTL on `main` is clean. |

---

## Injection

One term deleted from the write-commit condition, in both slaves:

```systemverilog
-  wire do_write = (aw_captured || aw_hs) && (w_captured || w_hs) && !bvalid_q;
+  wire do_write = (aw_captured || aw_hs) && !bvalid_q;   // BUG-002
```

The write now commits — and `BVALID` therefore asserts one cycle later — as
soon as **AW alone** has been accepted, with no regard for whether the write
data has arrived.

## Expected

Spec §3 rule 5: *"`BVALID` must not be asserted until both AW and W have been
accepted."* The registered-slave decision in §3 tightens this to exactly one
cycle after the **later** of the two accepts.

## Actual

`BVALID` asserted one cycle after the AW accept, with `w_captured == 0` and no
W handshake having occurred. The write committed using whatever happened to be
on `WDATA` at the time.

## Evidence

Cycle trace, register slave, 100 MHz clock. `awcap`/`wcap` are the DUT's own
accept-flags:

```
CYC 235000 | AWV=0 AWR=1 | WV=1 WR=1 | awcap=0 wcap=0 | BV=0     <- W accepted (legal W-before-AW case)
CYC 245000 | AWV=0 AWR=1 | WV=0 WR=0 | awcap=0 wcap=1 | BV=0     <- w_captured set, waiting for AW
CYC 265000 | AWV=1 AWR=1 | WV=0 WR=0 | awcap=0 wcap=1 | BV=0     <- AW accepted, both halves now held
CYC 275000 | AWV=0 AWR=0 | WV=0 WR=0 | awcap=0 wcap=0 | BV=1     <- BVALID, correct: follows the later accept
...
CYC 325000 | AWV=1 AWR=1 | WV=0 WR=1 | awcap=0 wcap=0 | BV=0     <- AW accepted ALONE, no W in sight
[335000] %Error: axi4lite_if.sv:224: Assertion failed in
         sanity_tb.dut.u_chk.a_bvalid_not_early:
         BVALID asserted before both AW and W were accepted
```

Note cycles 235000–275000: the W-before-AW case behaves correctly even with the
bug present. Only the AW-before-W ordering exposes it.

Memory slave, same injection, same assertion:

```
CYC 835000 | AWV=1 AWR=1 | WV=0 WR=1 | awcap=0 wcap=0 | BV=0
[845000] %Error: axi4lite_if.sv:224: Assertion failed in
         sanity_mem_tb.dut.u_chk.a_bvalid_not_early: ...
```

Waveforms: `sim/sanity_tb.vcd`, `sim/sanity_mem_tb.vcd`, failure at 335 ns and
845 ns respectively.

## Root cause

`do_write` is the single condition gating both the register/memory update and
the `BVALID` assertion. Removing the `(w_captured || w_hs)` term makes an
accepted AW sufficient to complete a write. There is no separate response FSM
to disagree with it, which is why one deleted term produces a clean, total
protocol violation rather than a partial one.

## Fix

Restore the deleted term. `main` has never carried the defect.

## Three experiments, and what they establish

Running the injection three ways gives a sharper result than "the assertion
fired".

### 1. Assertion bound — caught at the moment of violation

The assertion fires at 335 ns (register) and 845 ns (memory), naming the defect
directly: *BVALID asserted before both AW and W were accepted*. The register
bench had passed 8 checks at that point, the memory bench 20.

### 2. No checker bound — caught late, as a symptom

| Bench | Result |
|---|---|
| `sanity_tb` | **12 of 31** checks fail |
| `sanity_mem_tb` | **2 of 27** checks fail |

The functional checks do catch it — but as data corruption, not as a protocol
violation. The first register-slave failure is:

```
FAIL   AW-before-W data landed    0x12345678  (expected 0x0f0f0f0f)
```

`0x12345678` is the **previous transaction's** data: the write committed before
the new `WDATA` arrived. The remaining eleven failures are downstream
corruption, not independent findings.

The memory slave is the more instructive case. Only **2 of 27** fail, both data
mismatches, and one of them is `word 5 survives reset` — a check about reset
behaviour failing for reasons that have nothing to do with reset. Debugging
that trail leads toward the byte-masking logic. The defect is in the response
path.

**This is the argument for the protocol checker in one number:** the assertion
names the cause; the functional checks report symptoms that point somewhere
else.

### 3. Assertion bound, but the AW-before-W stimulus removed

```
RESULT: all 31 checks passed
```

No assertion fires. No check fails. **The bug is completely invisible.**

`do_write` differs from correct behaviour only when AW is accepted while W has
not been. Same-cycle and W-before-AW both leave the condition unchanged. Every
other write in the bench uses same-cycle ordering, so with that one stimulus
removed the corner is never entered.

This is the finding worth carrying forward. A bound assertion is **necessary
but not sufficient** — with no stimulus reaching the corner, the checker is
silent and the run is green. It is also why the AW-before-W case had to be
added to `sanity_tb` before this experiment could run at all: the original
bench had same-cycle and W-before-AW, but not AW-before-W.

Cover point `c_aw_before_w` is what makes this bug findable. A coverage model
is not bookkeeping for a report — it is the record of which defects the
regression is currently capable of detecting.

## Regression

After reverting, on `main`:

```
make test         31/31 sanity_tb, 27/27 sanity_mem_tb, no assertions fired
make test SIM=icarus   same, functional only
make lint         clean
```

## Note on BUG-001

Spec §9 pairs BUG-001 with `a_awvalid_stable` and injects it into the **driver**,
not the DUT. It is not covered here: there is no UVM driver yet, and the sanity
benches drive VALID correctly by construction. BUG-001 belongs to the UVM
milestone and is still outstanding.
