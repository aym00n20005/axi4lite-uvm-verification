# BUG-006 — COUNTER not cleared by CTRL.reset_stats

*Injected for qualification. Spec §9.*

| Field | Content |
|---|---|
| **ID** | BUG-006 |
| **Class** | Injected — not a genuine defect |
| **Detected by** | **Directed test**, as §9 requires |
| **Test + seed** | `f26_test` (`tb/uvm/bug006_min_tb.sv`), directed, Xcelium `SVSEED default: 1` |
| **Date** | 27 August 2026 |
| **Status** | Detected, reverted. `main` has never carried it. |

---

## Injection

One branch removed from the counter in `axi4lite_reg_slave`:

```systemverilog
   if (!ARESETn)               counter_q <= 16'h0;
-  else if (reset_stats_pulse) counter_q <= 16'h0;
   else if (ctrl_enable)       counter_q <= counter_q + 16'd1;
```

`CTRL.reset_stats` no longer clears `COUNTER`.

## Expected

Spec §5: `reset_stats` written as 1 clears `COUNTER` **with priority over
increment** — if `enable` and `reset_stats` both apply on the same cycle the
result is 0.

## Result

| | injected | clean |
|---|---|---|
| `CTRL enable=1, reset_stats=0` | PASS | PASS |
| `COUNTER is running (nonzero)` | PASS | PASS |
| `reset_stats cleared COUNTER` | **FAIL** `0x15` | PASS `0x00` |
| `COUNTER frozen while disabled` | **FAIL** `0x15` | PASS `0x00` |
| `reset_stats did not disturb enable` | PASS | PASS |

## The failure mode is not what the test comment originally claimed

The comment said a counter that `reset_stats` failed to clear *"would be
climbing here"*. It does not. The `CTRL = 0x2` write clears `enable` as well as
pulsing `reset_stats`, so under the injection the counter **freezes at its
uncleared value** — `0x15` on both reads, not a rising count.

The check fails either way, but the comment would have sent the next reader
looking for the wrong symptom. Corrected in both this bench and
`tb/sequences/axi_seqs.sv`, which carried the same wrong claim.

## The positive control is load-bearing

```systemverilog
repeat (4) rd(`A_SCRATCH, d);
rd(`A_COUNTER, d);
`uvm_info("F26", $sformatf("  COUNTER before clear = 0x%08h", d), UVM_LOW)
ck("COUNTER is running (nonzero)", (d != 0), 1'b1);
```

Without this, a counter stuck at zero for any unrelated reason sails through
*"reset_stats cleared COUNTER"* and the qualification proves that zero equals
zero. The clean run logs `0x00000011` — 17 and genuinely counting — so the
subsequent `0x00000000` means something.

The first version of this check printed the *comparison result* rather than the
observed value, so the log read `0x00000001` and looked as though the counter
were 1. A positive control that does not show its evidence is barely a control.

## Also caught by the scoreboard, which §9 did not require

`COUNTER` is free-running, so the reference model had skipped it unconditionally
since it was written. That was correct but too coarse: after a `reset_stats`
write with `enable` clear, `COUNTER` is 0 and **frozen there**, and every read
must return exactly 0 until `enable` is set again.

```systemverilog
SB_COUNTER : mask = m_counter_zero ? 32'hFFFF_FFFF : 32'h0;
```

`m_counter_zero` follows the RTL's own branch priority — enable set means
running and unknown; `reset_stats` with enable clear means zero and frozen;
neither means frozen at whatever it held.

So the model went from *"unpredictable"* to *"unpredictable except when it
isn't"*, and the difference is an entire §9 obligation. The full environment
(`playground_smoke`) now catches this bug without anyone having written a
directed check for it.

## Minimal bench

`tb/uvm/bug006_min_tb.sv`, 7.3 KB — written because EDA Playground's paste
limit could not take the full 2100-line bundle. No monitor, scoreboard,
coverage or randomisation; §9 asks only for a directed test here.

Two things were kept deliberately: the clocking-grid alignment from BUG-009,
without which the bench hangs, and the time-zero signal hold, without which
`a_reset_valids_low` fails at 5 ns on X.

It also cost one compile to a rule worth knowing: **a virtual method override
must reuse the base class's formal argument names.** `build_phase(uvm_phase ph)`
is `*E,CVMNMM` against `build_phase(uvm_phase phase)`. Abbreviating it saved 40
characters, which is exactly the mistake a size limit encourages.

## Fix

Restore the `reset_stats_pulse` branch. `main` never carried the injection: it
was applied, the design pane generated, and the RTL reverted in the same step.

## Regression

Clean: 5/5 on the minimal bench; local non-UVM regression 31/31 and 27/27.
